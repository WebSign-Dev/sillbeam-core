# Upgrade from Core 0.3.0 to 0.4.0

Update the Core version constraint from your application directory:

```bash
composer require websign-dev/sillbeam-core:^0.4.0
```

An existing `^0.3.0` constraint stays on the 0.3 line. The package name,
namespace, bundle, descriptors, registries, `sillbeam` configuration alias
and existing route import carry forward. Keep your native service exclusions
and explicit service and Doctrine overrides. The maintained local test matrix
covers PHP 8.4/8.5 with Symfony 7.4/8.1. See the [release notes](../releases/0.4.0.md#compatibility-and-scope)
for the exact patch versions and the Symfony 8.0 resolution limit.

## Console, API and graph

Keep `Sillbeam\Core\Console\Application` selected in the existing
`bin/console` bootstrap for fresh architecture diagnostics and the Core Data
commands. The application's kernel and Symfony Runtime callback stay in place.
See the [CLI setup](../reference/cli.md#enable-reporting-before-container-compilation).

Legacy `sillbeam:architecture --format=json` and `sillbeam:doctor --format=json`
still use schema v1. Keep the existing commands for consumers of those
schemas. Use [Core Data v1](../reference/core-data/README.md) when a consumer
needs Live or Analysis with their own JSON schemas and exit statuses. Human
output can be localized through `--locale`, `sillbeam:locale` or
`sillbeam.locale`. Graph 2.0 changes the SVG layout, so update SVG snapshots
that compare layout or bytes. `--format=mermaid` stays available for raw Mermaid.

## Deployment checks

Review discovery paths before rollout. An explicitly configured required
source root must resolve to a directory. Conventional Module and Project
directories may still be absent. Build fresh caches for each production release
and run the architecture check with the Core Console adapter before switching
traffic:

```bash
APP_ENV=prod APP_DEBUG=0 php bin/console cache:clear
APP_ENV=prod APP_DEBUG=0 php bin/console cache:warmup
APP_ENV=prod APP_DEBUG=0 php bin/console sillbeam:architecture --format=json
```

Require exit 0 from all three commands. Maintenance success by itself can
accompany an invalid architecture with deferred Core integration. Repair the
reported findings, then rebuild the release cache and repeat the checks. Warm
production HTTP serves the compiled state. A cold non-debug request returns
503 before source analysis.

## Cache and PHP process boundaries

The optional static source index uses `var/sillbeam/source-index`, separately
from the default Symfony cache. Core revalidates source contents on analysis
and reparses when cached entries cannot be reused. The index is disposable and
does not supply runtime activation. Keep the directory and its parents under
the project's trusted filesystem permissions. The [cache reference](../reference/architecture-analysis.md#source-index-and-cache-invalidation)
describes invalidation and fallbacks.

When source changes during an Analysis export, check the resulting completeness
and graph state. Restart a long-lived PHP process to load a changed descriptor
before running a fresh analysis. PHP retains definitions already loaded in that
process.

For older upgrades, keep the historical guides for [0.2.0](0.2.0.md) and
[0.3.0](0.3.0.md). Existing Flex and manual installations continue to use the
same bundle and route import. See [Flex installation](../guides/flex-recipe.md)
for the configured recipe source.
